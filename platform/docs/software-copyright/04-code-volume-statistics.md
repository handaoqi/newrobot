# 六个模块代码量统计

统计日期：2026年8月3日  
统计用途：软著源程序材料规划，不作为财务工时或研发投入核算依据

## 一、统计口径

1. 统计当前工作区中的Vue、JavaScript和Python自研候选文件。
2. 排除测试、数据库迁移、依赖包、虚拟环境、构建产物、缓存、日志、模型权重和第三方ROS/Nav2/SDK源码。
3. “物理行”使用文件总行数；“非空行”排除空白行，但仍可能包含注释，因此不等同于严格的有效代码行SLOC。
4. 一个文件同时承载多个模块时允许出现在多个候选集合中；表中明确标注共享关系，不能将六项数字直接相加作为项目唯一代码量。
5. `models.py`、`views.py`、`serializers.py`、公共API、协议和边缘通信等公共核心代码单独统计，未重复加入各模块合计。

## 四、公共核心代码

以下公共文件合计10个、6,561个物理行、5,727个非空行，包含数据模型、业务API、序列化、路由、通信协议和边缘公共通信。它们实际服务于多个模块，因此没有整体重复加入六项统计：

- `backend/monitoring/models.py`
- `backend/monitoring/views.py`
- `backend/monitoring/serializers.py`
- `backend/monitoring/urls.py`
- `backend/monitoring/protocol.py`
- `frontend/src/services/api.js`
- `frontend/src/router/index.js`
- 机器人端`config.py`
- 机器人端`mqtt_client.py`
- 机器人端`protocol.py`

正式制作每项源程序时，只抽取与该项功能直接相关且权属清楚的连续章节。例如ZC-06应选择轨迹模型、批次接收、轨迹查询和时间线接口，而不是把整个`views.py`重复放入六项材料。

## 五、项目可统计代码池

按前端源码、中心监测后端、板端识别程序和机器人Edge Agent整体扫描，并采用相同排除规则，当前共有88个可统计候选文件、25,333个物理行、22,686个非空行。该数字是候选代码池规模，不代表六项软著互相独立代码量之和。

## 六、软著材料建议

- ZC-03和ZC-04可直接从独立候选文件中组织60页连续代码。
- ZC-01、ZC-02、ZC-05和ZC-06需要加入各自相关的公共模型、API、序列化或通信代码。
- 每项目标准备不少于3,200个非空候选行，留出页眉、分页、超长行调整和敏感信息清理空间。
- 最终以“前30页+后30页连续源程序”的真实性和模块辨识度为优先，不以堆叠行数为目标。
