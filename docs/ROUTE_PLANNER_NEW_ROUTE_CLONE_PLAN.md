# 路径规划新建路线与另存为新路线计划

## 目标

- 页面首次打开时继续保留自动选择最近执行路线的现有逻辑。
- 路线选择框第一项改为“新建或选择已保存线路”；用户手动选择该项时清空编辑器并进入新建状态。
- 选择已有路线并修改后，点击“新建路线”将当前内容以新名称、新路线 ID 另存，不覆盖原路线。
- 路线名称重复时禁止创建，提示修改名称后再新建。

## 执行步骤

1. 抽取统一的新建编辑器清理逻辑，清理路线与演练状态但保留地图、机器狗和场景范围。
2. 为路线选择框增加新建哨兵选项；只在用户选择第一项时触发清理，首次加载自动路线逻辑不变。
3. 增加“新建路线”按钮，复用当前编辑器 payload，始终通过 POST 创建新路线 ID。
4. 增加前端和后端路线名称重复校验，重复时不覆盖、不自动切换，只提示改名。
5. 新路线创建成功后刷新列表、选中新路线，并复用现有地图激活、导航栈启动和初始化定位流程。
6. 增加前端交互、重复名称、POST/PUT 分流和后端校验测试。

## 验收标准

- 首次打开仍可自动加载最近执行路线。
- 手动选择“新建或选择已保存线路”后，路线内容被清空且不请求路线详情。
- 已有路线修改后点击“新建路线”生成新 ID，原路线不变。
- 重名时不发送创建请求，页面提示“路线名称已存在，请修改名称后再新建”。
- 普通“保存路线”对已有路线仍执行更新，对新建状态执行创建。
