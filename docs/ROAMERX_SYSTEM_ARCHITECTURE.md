# RoamerX 系统总体架构

更新时间：2026-08-24

## 1. 系统边界

RoamerX 由云平台、NX Edge Agent、3588 厂商运动控制系统和浏览器前端组成。云平台负责业务事实、任务编排、媒体元数据、命令审计和网页展示；NX Edge 负责断线可恢复执行、设备适配和现场数据上报；3588 负责厂商运动控制与充电状态。

```text
浏览器 Vue 3 前端
   │ HTTPS / SSE / HTTP-FLV 或 HLS
   ▼
云平台 Django API + 媒体服务 + 任务调度
   │ MQTT / HTTP
   ▼
NX Edge Agent + 本机 SQLite
   │ SSH / 厂商接口
   ▼
3588 运动控制与充电系统
```

## 2. 关键业务链路

机器狗摄像头经板端采集、推流和媒体服务生成 FLV/HLS 地址。前端进入监测中心或保安值守时先渲染页面骨架，再异步连接视频；视频连接期间显示加载状态，失败时显示无信号，不阻塞任务、告警和设备摘要的查看。

地图提供坐标系和底图，路径保存地图、途经点、方向、定位方式、避障和播报配置，任务模板绑定机器人与路线，日历负责自动执行时间，执行记录负责状态、轨迹和事件审计。

前端只通过统一 API service 发起命令。云平台记录命令生命周期，Edge 依据命令 ID 和消息 ID 幂等执行并回报状态；导航、接管、急停、回充等物理动作不因 UI 布局调整而改变 payload、安全停止或超时语义。

## 3. 前端显示约束

- 页面框架、状态卡片、错误态和空态独立于视频流加载。
- 监测中心、保安值守和远程控制通过 `DashboardLayout.vue` 的 `SharedLiveVideoHost` 与 `useSharedVideoStream` 共享视频源；页面只提供 `shared-video-slot`，播放器实例、媒体元素、定时器和事件监听器由共享宿主统一创建与销毁。
- 监测中心和保安值守支持浅色/深色主题，卡片和文字保持可读对比度。
- 路径规划顶部展示步骤 1—4，步骤可折叠；地图占主要区域，导航测试位于主卡片右下区域。
- 所有机器狗地图图示引用同一份 `platform/frontend/src/assets/robot-dog.svg`。

### 3.1 工作台导航显示契约

- 桌面设备无论浏览器窗口多窄都保留左侧竖向菜单，不再切换成横向菜单或抽屉。
- 移动设备无论横屏或竖屏，都启用右上角圆形菜单按钮和右侧抽屉；固定横屏验收规格为 `2000×1200`。
- `DashboardLayout.vue` 通过设备标识选择导航模式，不以视口宽度或屏幕方向改变模式；抽屉支持遮罩、Esc、路由跳转关闭、当前子菜单展开和键盘焦点恢复。该变化只影响显示层，不改变鉴权、路由或 API。
- 登录、监测中心、保安值守和远程控制首批按可读单列重排；视频使用可用宽度和固定宽高比，控制区不依赖桌面整体 `zoom` 缩放。
- 主要按钮、菜单和表单控件保持至少 `44×44px` 的触控尺寸；页面允许纵向滚动，不允许出现非预期全局横向滚动。

## 4. 持久化边界与回退

业务数据库、Edge SQLite 和 3588 状态文件的职责沿用三端数据架构。前端只保存会话、主题等浏览器状态，不直接访问数据库，也不把真实运行数据或设备配置提交到源码仓库。

前端大改动按功能阶段独立提交。最低验收包括 `npm test`、`npm run build`、`git diff --check`、浅色/深色模式、视频失败恢复、页面卸载清理，以及 Playwright 的三档平板竖屏检查：`768×1024` WebKit、`800×1280` Chromium、`834×1194` WebKit。平板验收通过 `npm run tablet:capture` 生成固定模拟数据截图和布局报告，再通过 `npm run test:tablet` 断言横向溢出、触控尺寸、抽屉交互和视觉基线；测试不连接真实机器人，也不发送运动命令。
