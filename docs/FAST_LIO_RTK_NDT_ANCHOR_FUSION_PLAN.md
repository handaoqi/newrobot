# FAST-LIO 相对增量与 RTK/NDT 锚点融合实施计划

## 最终架构

定位输出采用全局锚点与 FAST-LIO 相对运动组合：

```text
T_map_base(t) = T_map_base_anchor(t0)
              * inverse(T_lio_base(t0))
              * T_lio_base(t)

等价于：
T_map_base(t) = UKF(T_map_lio) * T_lio_base(t)
```

- FAST-LIO 始终提供高频局部增量，是唯一连续运动源。
- UKF 只估计低频二维全局锚点 `T_map_lio=[x,y,yaw]`，不再次积分
  FAST-LIO 运动。
- RTK 提供固定解 XY 和双天线 yaw 锚点。
- NDT/VGICP 低频检查地图一致性，并可提供备用锚点观测。
- 正常阶段保持最近锚点；仅在确认漂移或航点停车事务中提交新锚点。
- FAST-LIO 断流或运动异常时停车恢复，禁止 RTK/NDT 成为连续导航源。

## 校正策略

- 每个绝对观测按自身时间戳匹配 FAST-LIO 位姿，再转换为
  `Z_map_lio = Z_map_base * inverse(T_lio_base)`。
- 路段 `ndt` 只允许 NDT 更新锚点，`rtk` 只允许 RTK 更新锚点，`ukf`
  允许两者按质量自适应协方差融合；未选来源仍参与健康监测。
- UKF 模式允许单源降级。两路均通过各自质量门但相互不一致时按协方差
  加权折中，不增加来源间冲突硬拒绝门。
- 行驶中创新达到 0.30 m 或 5 度且连续 3 个稳定样本后校正一次；回到
  0.20 m / 2.5 度安全带后重新武装。
- 所有停车航点（含最终点）无论创新大小均强制执行一次锚点更新；
  `pass_through` 不停车、不校正。
- A 点配置负责 A 点停车校正和 A 到 B 路段。首段使用第一个目标点配置。
- 锚点更新继续限速平滑应用，禁止重置 FAST-LIO 前端或产生 TF 跳变。

## 航点事务

```text
Nav2 到点
  -> 停车稳定
  -> require_yaw 航点原地对准配置的终止朝向
  -> 按当前航点策略发起一次性锚点事务
  -> UKF 融合并完成锚点平滑
  -> 未执行终止转向时，使用校正后的新鲜位姿复核点击点
  -> 已完成终止转向时，保留转向前的 XY 到点判定，不再回逼点击点
  -> 当前点动作、停留和播报
  -> 使用最新位姿计算下一点方向并原地对准
  -> 下发下一航段
```

- 来源不可用时保持暂停和零速度，持续低频等待，直到来源恢复、任务取消
  或任务被替换。
- 行驶中绝对来源暂时丢失但 FAST-LIO 健康、漂移未确认超限时，保留最近
  锚点继续行驶并告警；到下一个停车航点后等待强制校正。
- 下一航点方向由校正后当前位置计算；10 度内直接确认，否则原地旋转并
  要求连续 3 个新鲜样本进入 10 度容差。20 秒超时后停车暂停，不允许
  未对准直接发车。

## 接口与验收

- 新增一次性校正控制服务，使用任务、轮次、航点和校正代次组成的事务 ID
  保证幂等。
- `/localization/decision` 上报锚点来源、协方差、RTK/NDT 创新与权重，以及
  一次性事务的等待、融合、平滑、完成和失败状态。
- 单测覆盖时间对齐、yaw 环绕、质量权重、单源降级、双源折中、漂移锁存、
  强制事务、迟到结果隔离、来源恢复和对准失败保持。
- 回放和实机必须验证正常导航的连续来源始终为 `lio_imu`，并验证最终输出
  等于最近有效锚点乘 FAST-LIO 相对增量。

## Edge Agent 的 `/front_lidar/imu` 订阅

Edge Agent 对该话题的订阅只用于把 Mid-360 陀螺仪与 3588 BMI088 的角速度
模长做低频健康交叉检查，不参与定位融合、锚点估计或运动控制。当前运行配置
`imu_cross_check.enabled: false` 时不会建立该订阅；若运行图中仍能看到订阅，需
检查是否加载了旧配置或旧进程尚未重启。FAST-LIO 自己对该 IMU 的订阅不受此
开关影响。
