# 公园自主巡检任务计划

## 目标

基于公园地图，让机器狗从当前单点导航能力升级为固定路线自主巡检能力。目标场景为约 1.8 公里标准巡检路线、8 个重点点位、远程监看、定点停留、视频留痕和任务日志。

## 任务表

| 阶段 | 子任务 | 产出 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 明确巡检区域和点位 | 点位清单和路线草图 | 覆盖入口、主路、花景区、活动广场 |
| 2 | 建图和地图整理 | `map.pgm`、`map.yaml`、地图版本说明 | 地图可加载、定位可初始化 |
| 3 | 点位标注 | 点位编号、名称、x/y/yaw、停留时长 | 8 个点位可在地图上复现 |
| 4 | 单点导航验证 | 单点导航测试记录 | 到点成功率达到演示要求 |
| 5 | 巡检路线模型 | 路线 JSON/YAML 数据结构 | 可保存和加载固定路线 |
| 6 | 多点任务执行 | ROS2 或后端任务队列 | 自动按顺序到达多个点位 |
| 7 | 到点动作 | 停留、转向、拍照、播报动作 | 每个点位动作可配置 |
| 8 | 异常处理 | 暂停、取消、重试、跳点机制 | 单点失败不影响整条任务可控退出 |
| 9 | Web 控制台 | 路线列表、开始、暂停、取消、进度展示 | 操作员可一键触发巡检 |
| 10 | 日志留痕 | 时间戳、点位结果、截图或视频索引 | 可生成巡检记录 |
| 11 | 现场测试 | 空旷、低人流、高人流测试记录 | 形成问题清单和优化项 |

## 推荐开发顺序

1. 先把点位表和路线数据结构做出来。
2. 复用当前 `/api/nav/goal` 的单点导航，封装成多点队列。
3. 再做 Web 路线 UI 和任务进度。
4. 最后补日志、异常处理和定点动作。
