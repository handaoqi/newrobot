# 路径规划页面智能起终点规划计划

## 总体方案与实施阶段

在路径规划页面增加“智能规划”模式：选择起点和终点后，由机器狗在线调用现有 Smac Hybrid A*，基于当前激活地图、禁行边界和静态障碍生成净空居中的路径，再通过 Savitzky–Golay 碰撞校验平滑器处理，最后按约 4.5 米间距生成航点。

规划过程只计算路径，不发送导航目标、不产生运动指令。规划成功后先预览，用户确认后才整体替换当前途径点列表。

- 第一阶段提供机器狗在线真实规划，结果与现役 Nav2 全局代价地图和规划插件一致。
- 第二阶段提供云端离线规划，使机器狗离线、导航栈未启动或编辑历史地图时仍可生成路线。
- 两阶段使用相同的请求字段、结果结构、运动学参数、净空代价和航点采样规则；页面必须标明规划来源，不把云端估算伪装成机器人实时规划。

## 接口与算法改动

- 新增 `POST /api/robots/{robot_id}/navigation/plan-path/`：
  - 请求包含 `map_id`、`map_version`、`start{x,y,yaw}`、`goal{x,y,yaw}`、`spacing_m=4.5`。
  - 创建新的 `nav.plan_path` 远程命令并通过现有命令详情接口轮询结果。
  - 校验机器人在线、地图与机器人当前激活地图一致、坐标有效且不在外边界或禁入区内。
- Edge Agent 新增纯规划处理：
  - 调用 `ComputePathToPose`，明确指定 `SmacHybridStrict`。
  - 成功后调用 `SmoothPath`，优先 `savitzky_golay`，碰撞校验失败则整体失败。
  - 不调用 `FollowWaypoints`、`NavigateThroughPoses` 或任何速度控制接口。
  - 规划最长等待 45 秒、平滑最长等待 5 秒。
- 返回结果包含：
  - `planner_id`、`smoother_id`、地图版本、总长度和耗时。
  - 用于地图显示的简化平滑折线，最多 1000 点。
  - 起点、中间点和终点组成的自动航点数组及实际间距统计。
- 增加 `SmacHybridStrict` 规划器实例：
  - 与现役 Smac Hybrid A* 使用同一运动学和障碍参数。
  - 自动规划失败时禁止静默退回 NavFn，返回明确原因。
  - 现役 `SmacHybrid` 保留运行阶段原有回退能力。
- 强化 Hybrid A* 净空居中：
  - 每次规划从全局静态代价地图计算截断距离场。
  - 致命障碍、膨胀内接障碍和禁行边界视为零净空；未知区域允许通过但施加最高净空惩罚。
  - 使用 2 米净空评价半径和权重 3.0，使道路两侧都有障碍或边界时优先靠近几何中央；宽阔区域超过评价半径后仍优先最短路线。
  - 同样参数应用到运行阶段的 `SmacHybrid`，避免保存路线与实际分段重规划明显偏离。

## 页面与航点行为

- 地图工具栏增加“智能规划”，交互顺序为选择起点、选择终点、生成预览。
- 第二阶段完成后增加规划来源选择：
  - `自动`：机器人在线、地图一致且 Nav2 就绪时优先在线规划，否则使用云端离线规划。
  - `机器人在线`：只接受 Edge/Nav2 结果，失败时不自动切换算法。
  - `云端离线`：直接使用云端保存的地图文件，允许规划非活动历史地图。
  - 预览区始终显示“机器人 Smac Hybrid A*”或“云端兼容 Hybrid A*”来源标签。
- 起点支持：
  - 地图手动点选。
  - 一键采用机器狗当前可信位置和朝向；定位不可信或地图不匹配时禁用。
- 手动起点尚无朝向时，以起点到终点方向作为规划初始朝向；生成后所有航点方向按平滑路径切线计算，仍可在现有航点卡片中修改。
- 预览使用独立颜色显示，并展示总长度、航点数、最大间距、规划器和平滑器；现有航点在确认前保持不变。
- 点击“应用到途径点”时，如果列表非空先确认覆盖，然后生成：
  - 名称依次为“起点”“中间点1…”“终点”。
  - 常规路段目标间距 4.5 米，相邻航点不得超过 5 米。
  - 路径在 1 米观察窗口内转向超过 20°时补充转弯航点；转弯、起终点附近允许短于 4 米。
  - 所有生成点设置 `global_controller=smac_hybrid`、开启绕障/减速/硬停止，使用现有默认局部控制器。
  - 按已确认要求，所有点均使用 `stop_and_confirm`，不默认强制到点朝向；因此平滑指路径几何平滑，机器狗仍会约每 4.5 米停车确认。
- 切换地图、重新选择起终点或规划失败时清除旧预览，但不删除已有途径点。
- 错误需直接显示具体原因，包括机器人离线、地图未激活、Nav2 未就绪、起终点不可通行、Hybrid A* 无路径、超时和平滑碰撞校验失败。

## 第二阶段：云端离线规划

### 云端接口与作业模型

- 新增地图级异步接口：
  - `POST /api/maps/{map_id}/path-plans/` 创建离线规划作业。
  - `GET /api/maps/{map_id}/path-plans/{plan_id}/` 查询排队、运行、成功或失败状态。
  - 请求继续使用 `start`、`goal`、`spacing_m=4.5`，并记录地图文件校验值、边界生效版本和算法版本。
- 新增 `MapPathPlan` 持久化作业，保存请求、状态、耗时、失败代码、结果摘要和有限期完整结果；复用现有后台 worker 运行模式，避免 HTTP 请求长时间占用 Web 进程。
- 在线和离线结果统一返回 `source`、`algorithm_version`、`planner_id`、`smoother_id`、`distance_m`、`preview_path`、`waypoints` 和间距统计，前端只维护一套预览与应用逻辑。
- 作业完成后若地图文件校验值或生效边界版本已变化，结果标记 `stale=true`，禁止直接应用，要求基于新版本重新规划。

### 离线地图与规划实现

- 直接读取云端已经保存的 `map.pgm` 和 `map.yaml`，按照分辨率、原点、占用阈值和图像坐标方向构建二维栅格；不使用缩略图参与规划。
- 将生效外边界、安全距离和禁入区栅格化为不可通行区域；限速区和警告区第一版只随结果返回，不改变可通行性。
- 使用 NumPy/OpenCV 实现云端兼容 Hybrid A*，不在云服务器部署整套 ROS/Nav2：
  - 72 个朝向分箱、0.5 米最小转弯半径、0.1 米步长、禁止倒车、最大 200000 次扩展。
  - 与在线版本相同的障碍、转向变化、未知区域和 2 米净空距离场代价。
  - 起点、终点或机器人足迹与障碍冲突时直接失败，不退回普通 A* 或直线连接。
- 用固定九点二次 Savitzky–Golay 系数实现路径平滑，每次平滑后执行线段和机器人足迹碰撞检查；无法获得安全平滑结果时返回失败。
- 平滑后复用同一套 4.5 米自适应采样模块，生成与在线模式相同的航点字段和停车策略。
- 云端离线模式不使用实时激光、人车或机器人当前代价地图；机器人离线时只能手动选择起点，不能使用过期的最后位置冒充当前起点。

### 一致性与部署

- 建立在线/离线共享的参数清单和算法版本号，参数变更必须同时更新 Edge 配置与云端规划配置。
- 保存一组直路、弯道、窄通道、禁区和未知区域的标准 PGM/YAML 样例；在线插件与云端实现对同一输入比较可达性、路径长度、最小净空和航点数量。
- 一致性验收允许路径坐标不逐点相同，但要求可达结论一致、路径长度差不超过 5%、最小净空差不超过 0.15 米、航点数量差不超过 1 个。
- 云端 worker 设置单作业 45 秒和内存上限；失败作业保留错误摘要，完整预览结果按既有媒体/数据保留策略清理。

## 后续可扩展方向

以下方向不纳入前两阶段必做范围，按现有数据基础和收益排序：

1. **必经点与分段规划**：允许起终点之间添加少量必须经过的锚点，逐段 Hybrid A* 后统一平滑和采样，适合指定巡检走廊。
2. **多目标候选路线**：在同一地图上生成“最短、净空优先、少转弯”三种候选，并显示距离、最小净空和预计停车次数，不自动替用户选择。
3. **地图和边界变更影响分析**：地图或禁区更新后自动标出受影响路线，只重算与变化区域相交的路段，避免整条路线人工重建。
4. **三维可通行地形融合**：接入已有 `map_traversable`、点云和地形过滤结果，对台阶、坡度、草地和不可支撑区域赋予通行或风险代价；二维证据不足时仍按障碍处理。
5. **审核后的场景语义代价**：只使用已人工确认的墙体、建筑、树木等静态语义修正道路边缘和障碍代价；行人、车辆继续保持运行时动态处理。
6. **历史巡检风险热力图**：从定位丢失、重规划、急停和人工接管记录形成路段风险代价，支持“避开历史高风险区域”的候选路线。
7. **路线缓存与批量规划**：按地图校验值、边界版本、起终点和参数缓存结果，并为多个巡检目标批量生成路线；仅在离线规划量出现实际性能压力后实施。

优先建议在第二阶段后先做 1–3；4–6 依赖三维地形、语义审核和历史事件数据质量，达到覆盖率要求后再启用；7 属于规模化优化，不提前建设。

## 测试与验收

- C++ 规划测试覆盖直路居中、弯道、窄通道、禁入区、未知区域、无可行路径以及严格禁止 NavFn 回退。
- Edge Agent 测试验证规划与平滑调用顺序、超时和错误映射、4.5 米自适应采样，并断言整个流程从不调用运动接口。
- 后端测试覆盖坐标、地图版本、边界、在线状态、命令协议、结果持久化和错误返回。
- 前端测试覆盖手动起点、机器狗位置起点、两次点击、预览、覆盖确认、失败保留原列表以及地图切换清理。
- 云端离线测试覆盖 PGM/YAML 解析、坐标变换、边界栅格化、异步作业状态、地图版本过期、资源超限和在线/离线结果一致性。
- 使用约 100 米直路和包含急弯/障碍的测试地图验收：
  - 平滑路径不穿越障碍或禁行区。
  - 普通路段航点约 4.5 米一个且最大间距不超过 5 米。
  - 道路边界明确时路径明显偏向净空中央。
  - 应用后的每个航点均停车确认。
  - 规划操作不会让机器狗移动。

## 已确定假设

- 第一版道路居中是基于障碍和边界净空的几何居中，不依赖人工道路中心线或语义道路数据。
- 保存路线只考虑静态地图和禁行边界；行人、车辆等动态障碍继续由执行阶段的局部代价地图实时处理。
- 第一阶段真实规划要求机器狗在线、Nav2 就绪并激活所选地图；第二阶段使用云端保存的地图提供离线兼容规划。
- 云端离线规划保证规则和指标兼容，不承诺路径坐标与 ROS/Nav2 输出逐点完全相同；最终执行仍由机器人根据现场代价地图重新规划和避障。
- Hybrid A* 或平滑器失败即拒绝生成路线，不使用其他全局规划算法代替。
