# 导航中与目标点定位校正稳定性计划

## 目标

在 Fast-LIO2 连续定位、NDT/RTK 绝对观测和 UKF 融合的现有架构上，明确导航中与到达目标点后的校正行为。校正只改变定位状态或 `map→lio_odom` 锚点，不驱动机器人走向锚点。

## 当前实现（同步于 2026-09-16）

- FAST-LIO + IMU 是默认连续定位源；绝对观测只通过 `map→lio` 锚点平滑进入 UKF，不改写原始 `/odom/lio_odom`，也不驱动机器人向校正锚点移动。
- 正常低速巡航可执行受限在线锚点校正。Edge 只在 `running + moving` 的普通巡航阶段授权；最终靠近、到点、转向、XY 微调、避障/自愈、重定位、人工控制、暂停和停靠均明确禁止。
- 在线校正二次要求 LIO 新鲜且无异常、没有正在进行的锚点平滑、融合 profile 为 nominal、实测线速度 `≤0.15 m/s`、角速度 `≤0.10 rad/s`。在线 NDT 要求 score `<0.10`、内点率 `≥0.50`、样本年龄 `≤0.50 s` 和连续 3 帧稳定；在线 RTK 只接受 fixed，且要完成 `1 s / ≤0.35 m` 自稳定。float RTK 永不参与在线校正。
- 只有 XY `0.30～<1.00 m` 或可信 yaw `5～<10°` 的残差允许在线微调，锚点平滑速率为 `0.05 m/s`、`3°/s`，共享冷却门为最小间隔 `1 s`、校正后抑制 `1 s`。小于下限不校正；达到 `1.00 m` 或 `10°` 时标记绝对定位分歧、停车并进入重定位，而不是边走边追赶。
- 航点到达采用一次、幂等的静止校正事务：非 `pass_through` 航点先确认连续零速 1 秒，再切换 `stationary` 并按任务 ID、航点 ID、generation 创建事务。重复回调复用原事务；完成后才进入 XY/yaw 验收。细靠近或转向后 XY 微调发生新的实际移动时，必须重新停车、重新校正和复核。

### 到点校正选源

| 航点配置 | 静止后的选择与结果 |
|---|---|
| `ndt` | 仅 NDT；收敛、健康、新鲜且 score `<0.40` 时校正，否则 `ndt_no_correction_continue`。 |
| `rtk` | 仅 fixed RTK；float、过期或无效 RTK 不等待、不融合，结果为 `rtk_no_correction_continue`。 |
| `ukf` | 合格 fixed RTK 优先；无 fixed 时 NDT `<0.10` 用 NDT 单源；NDT `0.10～<0.40` 且 float RTK 残差 `≤0.40 m` 时按协方差融合；float 超限时硬拒绝并在 NDT 合格时退化为 NDT 单源。两者都不合格时结束事务，结果为 `ukf_no_correction_sources_meet_gate`。 |

所有“不校正继续”都仍要求 LIO 新鲜、无异常并再次确认停车；它不是伪造校正成功，也不会因等待 RTK fixed 而无限阻塞。

## 实施内容

### 定位模块

- 保留 UKF 和锚点平滑算法，持续发布校正模式、选源、质量门、残差、平滑进度、失败原因和地图版本信息。
- 导航中按“正常低速巡航可微调 / 超出在线带安全停车重定位”分级；在线更新只接受 NDT 或 fixed RTK，绝不接受 float RTK。
- 到点校正仅在标准停车确认完成后执行；停车判定使用里程计速度阈值和连续 1 秒保持，随后由一次性事务约束选源、平滑和完成态。
- 禁止过期、跳变、坐标/时间无效或地图版本不一致的观测修改锚点；UKF float RTK 还必须通过 `≤0.40 m` 的执行层硬门。

### 导航与航点模块

- 非穿越航点流程为 `ARRIVED → STOP_CONFIRMING → CORRECTING → VERIFYING → SUCCEEDED`；`pass_through` 仅记录经过，不停车、不校正。
- 校正和平滑期间持续输出零速度，待事务完成、平滑结束、LIO 新鲜后重新计算 XY/yaw；未达到策略半径时只按到点策略执行有界细靠近或转向后微调。
- 一次校正事务按任务 ID、航点 ID、generation 幂等。没有合格绝对源时显式完成为“不校正继续”；LIO 故障、样本陈旧、未确认停车或严重绝对分歧仍安全保持，不会放行。

### 监控与验证

- 上报校正源、前后位姿、增量、质量、耗时、状态和失败原因。
- 增加在线小/中/大误差、静止目标点、数据失效、重复回调、TF 稳定性和无非零速度测试。
- 现场验收室内 10 次、室外 5 次，并检查转弯、上下坡、多航点连续导航。

## 当前安全参数

- 在线校正残差带：XY `0.30～<1.00 m`，可信 yaw `5～<10°`；达到上界后禁止在线拉回并进入安全恢复。
- 在线运动限制：`v≤0.15 m/s`、`w≤0.10 rad/s`；在线 NDT 为 score `<0.10`、内点率 `≥0.50`、样本 `≤0.50 s`、连续 3 帧；fixed RTK 自稳定窗口为 `1 s / ≤0.35 m`。
- 在线平滑：`0.05 m/s`、`3°/s`；共享冷却门最小间隔 `1 s`、校正后抑制 `1 s`。静止校正平滑基线保持 `0.25 m/s`、`8°/s`。
- 静止确认保持 1 秒；每个正常到达阶段只创建一次事务。之后如发生真实细靠近或 XY 微调，则按“再次停车后重新校正”的安全规则复核。

## 实施进度（2026-09-16）

- 已完成：航点到达后发送零速度并确认实际速度稳定，再切换 stationary 定位策略；每次正常到达只创建一个可重放的校正事务。
- 已完成：Edge Agent 等待 `absolute_stable=true` 且 `correction_smoothing_active=false` 后才继续航点流程，避免在锚点仍平滑变化时恢复导航。
- 已完成：NDT/VGICP 最终校正函数再次强制检查 `is_converged`、fitness `< ndt_max_fitness_score`、状态健康和内点率 ≥ 0.05，避免其他调用路径绕过质量门。
- 已完成：RTK 最终校正函数再次强制检查 FIX、位置有限、时间戳、时效和水平标准差；RTK 模式下 float 不融合、不等待。
- 已完成：Edge Agent 在等待锚点平滑结束期间持续发送零速度，避免活动中的 Nav2 控制器覆盖一次性停止指令。
- 已完成：航点语音等待与定位校正并行执行；通过航点级同步标志，只有语音完成且 `correction_smoothing_active=false`、绝对定位稳定后才发送下一航点。
- 已完成：UKF 固定 RTK 优先、NDT `<0.10` 单源、`0.10～<0.40 + float≤0.40m` 融合、float 超限拒绝和三类“不校正继续”均已落地并覆盖边界测试。
- 已完成：Edge 的在线授权、到点事务复用、无校正完成后再次零速确认等目标测试通过。
- 已完成：NDT 无有效地图搜索树时内点率不再回退为 1.0，直接判为几何证据无效并拒绝校正。
- 已确认：路径规划页和任务执行页已消费 `correction_smoothing_active`、校正源、候选源、稳定帧等定位决策字段，前端生产构建通过。
- 待完成：现场回放/实机验收，覆盖低速直行、转弯、fixed RTK 跳变、float RTK、严重绝对分歧和多航点连续执行。
