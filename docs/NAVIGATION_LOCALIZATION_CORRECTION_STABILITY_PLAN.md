# 导航中与目标点定位校正稳定性计划

## 目标

在 Fast-LIO2 连续定位、NDT/RTK 绝对观测和 UKF 融合的现有架构上，明确导航中与到达目标点后的校正行为。校正只改变定位状态或 `map→lio_odom` 锚点，不驱动机器人走向锚点。

## 当前实现

- Fast-LIO2 在 LIO 主模式下持续进入 UKF；NDT/VGICP 和 RTK 经过漂移门限、连续稳定帧和冷却门控后作为间歇绝对校正源。
- 校正通过 `scheduleLioAnchorCorrection()` 排队，并由 `advancePendingLioCorrection()` 以受限速度平滑调整锚点，再将修正后的 LIO 位姿交给 UKF。
- 当前配置默认漂移触发为 0.30 m/5°、连续 3 帧、校正间隔 3 s、锚点平移 0.25 m/s、旋转 8°/s。
- Edge Agent 到达航点后会停止运动、切换 stationary 定位策略并等待绝对定位稳定，但还需要明确静止确认失败、校正中状态和目标点二次确认行为。

## 实施内容

### 定位模块

- 保留现有 UKF 和锚点平滑算法，增加校正模式、状态、失败原因和地图版本信息。
- 导航中采用小/中/大误差分级：小误差平滑在线修正，中等误差零速保持后修正，大误差拒绝并进入重新定位。
- 目标点校正只在速度低于 0.03 m/s、角速度低于 2°/s 并稳定 1 s 后执行。
- 继续使用 NDT 3D 匹配或 RTK FIX 质量门限；禁止过期、跳变或地图版本不一致的观测修改锚点。

### 导航与航点模块

- 航点状态扩展为 `ARRIVED→SETTLING→CORRECTING→VERIFYING→SUCCEEDED`。
- 校正期间输出零速度、抑制不必要的重规划，校正完成且 TF 稳定后恢复导航。
- 目标点校正后重新计算目标误差；仍在容差内才完成，否则有限次数继续微调导航。
- 所有请求按任务 ID、航点 ID、地图版本幂等，失败和超时有界退出，不阻塞整条线路。

### 监控与验证

- 上报校正源、前后位姿、增量、质量、耗时、状态和失败原因。
- 增加在线小/中/大误差、静止目标点、数据失效、重复回调、TF 稳定性和无非零速度测试。
- 现场验收室内 10 次、室外 5 次，并检查转弯、上下坡、多航点连续导航。

## 默认安全参数

- 在线小误差：≤0.08 m、≤2°；中等误差：≤0.30 m、≤5°；更大误差拒绝在线拉回。
- 静止确认 1 s，单次校正最长 2 s，校正冷却 3 s，目标点最多校正 2 次。
- 不直接覆盖现有全局门限，新增 `online_correction_*` 和 `goal_correction_*` 参数。
