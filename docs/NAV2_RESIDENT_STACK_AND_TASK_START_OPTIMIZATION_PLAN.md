# Nav2 常驻与任务启动优化实施计划

## 目标

在不采用执行组 active 常驻的前提下，保持 Nav2 进程和定位节点常驻，执行组默认处于 `configured/inactive`，同地图且定位稳定时跳过重新 NDT，将重复任务启动耗时控制在约 3～5 秒，并保留定位、地图和速度安全门。

## 当前实现基础

- `navigation_stack_adapter.prepare()` 已支持复用已运行的 Nav2 进程。
- `TaskExecutor` 已在 FAST-LIO/NDT 稳定时复用当前定位，跳过 progressive NDT。
- 地图切换和定位恢复会停用执行组，避免旧地图或旧定位继续驱动导航。
- 任务启动仍会经过执行组激活和 ready 检查，激活阶段存在重复状态探测和耗时未分段记录问题。

## 实施内容

1. 保持 Nav2、localization、地图服务进程常驻；普通任务结束、暂停和取消时取消旧 action、清理 BT 状态、确认速度为零，然后将执行组置为 `configured/inactive`。
2. 稳定定位复用必须同时满足地图 `map_id/map_version` 一致、定位源有效、状态正常、LIO 样本新鲜、连续稳定、无运动异常、无定位恢复和地图切换事务；室外额外校验 RTK 与当前位姿一致。
3. 对任务启动记录 `prepare`、定位复用判断、生命周期激活、ready 检查和首航点下发的独立耗时。
4. 已知执行组为 `configured/inactive` 时跳过重复完整 status 预探测；激活成功后仅进行短时 ready 确认，异常时恢复完整探测和安全回滚。
5. 任一旧 action 未清理、速度未清零、地图/定位不一致或安全状态异常时，禁止激活或下发首航点。

## 回退和边界

- 定位复用条件不满足时继续完整 NDT/FAST-LIO 初始化，不降低质量门。
- 地图切换、定位丢失、执行组激活失败时保持 inactive；激活失败执行 deactivate 回滚。
- `nav.stop`、严重故障和进程异常仍允许完整停止或重启 Nav2。
- 不并行绕过 Lifecycle Manager 激活节点。

## 验收指标

- 连续 10 次同地图任务启动，Nav2 进程 PID 不变化。
- 稳定定位场景不调用 progressive NDT，并输出明确的复用证据。
- 任务开始前执行组为 `configured/inactive`，激活后所有执行节点为 active。
- 任务切换期间 `/cmd_vel` 保持零，旧 action 不再回调推进航点。
- 稳定定位复用场景从任务接受到首航点下发约 3～5 秒。
- 定位不稳定、地图变化和激活失败路径均安全回退并返回明确原因。
