# 远程协作建议

## 推荐工具

GitHub 私密仓库很适合这个项目，原因是它能同时解决代码备份、多人协作、分支管理、Issue 任务拆分和代码评审。建议先用 GitHub Private Repo，不要一开始上太重的平台。

## 分支流程

推荐使用下面的轻量流程：

1. `main`：稳定分支，能跑通控制台和基本机器人连接。
2. `dev`：集成分支，日常把多人开发结果合进来。
3. `feature/xxx`：个人功能分支，例如 `feature/patrol-route`、`feature/waypoint-ui`。
4. 合并时走 Pull Request，至少让另一个人看一眼。

## 代码分层

建议把项目分成这些模块：

- `dog_mvp_platform/`：Web 控制台、HTTP API、地图显示、导航下发。
- `robot_ws/`：自己写的 ROS2 包，例如巡检任务、点位管理、日志记录。
- `scripts/`：部署、同步、启动、诊断脚本。
- `docs/`：方案、接口、点位表、测试记录。

目前仓库里已经有 Web 控制台。机器狗本体上的 ROS2 代码需要再同步一遍，尤其是 `/home/jszr/robot_navigation` 这类自己写的工作空间。不要把 `/opt/robot` 或系统安装包直接提交，它们更像运行环境依赖。

## 机器狗端代码怎么管

建议以后采用这个习惯：

1. 在电脑或云服务器上写代码，提交到 GitHub。
2. 机器狗上 `git pull` 最新代码。
3. 在机器狗上 `colcon build` 和运行测试。
4. 如果现场临时在机器狗上改了代码，立刻提交到分支并推回 GitHub。

这样机器狗不会变成唯一代码源，也不会出现“到底哪份代码最新”的问题。

## 不要上传的内容

- 明文密码、密钥、token、访问说明。
- 反向隧道日志、PID 文件。
- `__pycache__`、虚拟环境、构建产物。
- 录制数据包、点云、地图大文件，除非特意做了小型示例。
- 生成的 PDF、临时渲染目录、压缩包。
