# 定位、视频识别与避障链路降载稳定性计划

## 1. 现状结论

- 稳定 FAST-LIO 的非 NDT 帧已经只执行 LIO 到 UKF 更新，不进行 ROS 到 PCL、点云预处理、坐标转换和 NDT/VGICP 匹配。
- 当前所谓“稳定”主要依据 LIO 主源启用且里程计时间新鲜，缺少连续健康帧确认。
- `ndt_stride=5` 在当前约 10 Hz 点云下约等于 2 Hz，但只是帧计数抽样，输入频率升高时会超过 2 Hz，因此目前不是严格的 2 Hz 上限。
- 当前视频读取约 30 Hz、模型实际推理约 14–16 Hz，`person_report_interval_seconds` 只限制上报，不限制模型推理。
- 避障链路约 10 Hz，属于安全链路，不应整体降到 2 Hz；主要优化重复转换和重复处理。

## 2. FAST-LIO、NDT/VGICP 调度

- 在现有 `ndt_stride` 基础上增加单调时钟限频。稳定阶段只有同时满足以下条件才运行 NDT/VGICP：
  - 本帧命中 `ndt_stride`；
  - 距离上次匹配开始至少 0.5 秒；
  - FAST-LIO 连续健康、定位已初始化；
  - 当前没有重定位、LIO 失效恢复或校正平滑任务。
- 稳定阶段 NDT/VGICP 最大 2 Hz；实际频率为 `min(点云频率/stride, 2 Hz)`。
- 初始化、全局重定位和 LIO 失效恢复使用独立上限 5 Hz，保留恢复速度。
- 增加连续 3 帧健康确认：LIO 时间新鲜、位姿有限、单帧跳变未超限且上一帧成功进入 UKF 后，才进入稳定调度。
- 未命中重匹配条件的帧只执行 LIO/UKF、状态和里程计发布，不创建 PCL 点云、不进行滤波、转换、NDT 或 VGICP。
- `lio_primary=false` 时保留现有 NDT 主定位行为；RTK 主定位暂停点云匹配的规则保持不变。
- 计划性跳帧、校正冷却和限频不计作 NDT 失败，不得触发错误的重定位或“匹配不健康”。

## 3. 校正冷却和防连续跳变

- NDT/VGICP 与 RTK 共享同一套全局校正时间门控，避免两个辅助源交替校正。
- 保留现有偏差阈值、匹配质量、连续 3 帧稳定、动态协方差、单次校正锁存和平滑应用规则。
- 两次校正开始时间至少间隔 3 秒。
- 校正平滑完成后再屏蔽新校正 3 秒。
- 平滑期间和完成后的屏蔽期内跳过不具备执行价值的 NDT 重匹配。
- LIO 失效、初始化和人工或自动重定位不受该冷却限制。
- 诊断状态增加实际 NDT 频率、重处理频率、跳帧原因、校正剩余冷却时间、最后校正源和开始/完成时间。

## 4. 视频识别降频

- 只修改当前实际部署的 `platform/bot-version-test` 链路。
- 摄像头抓流和视频推流保持原频率，推理线程按单调时钟从最新帧采样，禁止积压旧帧。
- 默认识别频率设为 2 Hz；人员跟随启用时自动切换到 5 Hz，退出后立即恢复 2 Hz。
- 人员模式查询与推理调度分离，等待期间使用事件等待，不能忙循环。
- 性能日志增加目标频率、实际推理频率、采集帧号跨度、输入帧年龄和模式切换记录。

## 5. 避障点云效率

- `/front_lidar -> /laser_scan_raw -> /laser_scan -> collision_monitor` 保持约 10 Hz，碰撞监控继续按控制命令频率响应。
- Collision Monitor 按 LaserScan 时间戳缓存已转换的二维点；同一张 10 Hz 扫描被 20 Hz 控制循环重复使用时，不再重复 TF 查询、三角函数和点集重建。
- 当扫描本身已经处于 `base_link` 时走无 TF 转换快速路径；其他坐标系仍执行原有 TF 检查。
- `self_filter_scan` 缓存角度对应的正余弦值并复用，减少逐帧三角函数计算。
- 避障链路不裁掉360度数据，确保室内重新启用局部代价地图时仍能处理侧后方障碍；该安全视场独立于建图、导航FAST-LIO和NDT/VGICP统一采用的前向240度定位点云。
- 增加扫描接收频率、处理频率、扫描年龄、点数、缓存命中率及处理耗时诊断。

## 6. 配置接口

```yaml
source_arbiter:
  stable_ndt_max_rate_hz: 2.0
  recovery_ndt_max_rate_hz: 5.0

lio_primary:
  stable_confirmation_frames: 3
  correction_gate:
    min_interval_seconds: 3.0
    post_suppression_seconds: 3.0

detection:
  inference_rate_hz: 2.0
  person_follow_inference_rate_hz: 5.0

collision_monitor:
  scan:
    cache_by_stamp: true
    performance_log_interval_seconds: 10.0
```

频率参数设为 `0` 时关闭对应墙钟限频并回退到原有 stride 行为；缓存参数设为 `false` 可恢复原避障实现。

## 7. 测试、部署与验收

- 单元测试覆盖 stride 与墙钟双门控、10/20 Hz 输入、初始化 5 Hz 例外、LIO 掉线恢复、跨 NDT/RTK 冷却、校正完成后 3 秒屏蔽、时钟回退以及视频 2/5 Hz 切换。
- 避障测试覆盖同一时间戳只转换一次、新扫描立即更新、扫描超时、TF 失败、并发回调和急停/减速区域判断。
- 部署前采集同场景 10 分钟 CPU、内存、频率和延迟基线；完成构建测试后依次重启定位、导航和视频服务。
- 执行 60 分钟全链路稳定性测试，并单独进行人员跟随 5 Hz 和受控障碍物测试。
- 验收标准：
  - 稳定定位阶段 NDT/VGICP 滚动 30 秒频率不超过 2.1 Hz，LIO 和定位里程计保持至少 8 Hz；
  - 普通视频推理为 1.8–2.2 Hz，人员跟随为 4.5–5.5 Hz，无旧帧队列增长；
  - 相同场景下视频进程平均 CPU 至少下降 50%，定位进程平均 CPU 至少下降 30%；
  - `/laser_scan` 保持至少 8 Hz，P95 数据年龄不超过 200 ms，障碍触发到速度抑制不超过 200 ms；
  - 60 分钟内无服务重启、崩溃、OOM 或持续升高的负载，进程 RSS 增长不超过 10% 或 100 MiB；
  - 任意两次校正开始至少间隔 3 秒，校正完成后 3 秒内不得出现新校正，轨迹无瞬时跳变。

## 8. 实施约束

- 现有定位性能优化代码尚有未提交修改，实施时在其基础上补充，不覆盖其他会话或用户修改。
- 避障安全链路不降为 2 Hz；降频仅作用于定位重匹配和视频推理。
- 默认采用“稳定 NDT 不超过 2 Hz、初始化或恢复允许 5 Hz”和“普通识别 2 Hz、人员跟随 5 Hz”。

## 9. 实施与验收记录（2026-08-30）

- 已实现 FAST-LIO 稳定帧确认、stride 与单调时钟双门控；稳定 NDT/VGICP 上限 2 Hz，初始化/恢复上限 5 Hz。
- 已实现 NDT 与 RTK 共享校正门控：两次校正至少间隔 3 秒，平滑完成后继续屏蔽 3 秒。

- 已实现碰撞监控同时间戳扫描缓存、`base_link` 快速路径、SensorData QoS KeepLast(1)，以及自过滤三角函数缓存。
