# FAST-LIO-SAM ENU、GPS与标准IMU因子统一改造计划

## 1. 总结

基于现有 `robot_slam`/FAST-LIO-SAM 实现，不引入上游 LIO-SAM。室外建图流程固定为：

```text
锁定RTK原点
→ 停止Nav2和localization
→ 启动专用ENU转换节点
→ 严格注入lat0/lon0/alt0
→ 启动FAST-LIO-SAM
→ useGPS:true、useImuFactor:true
→ 激光、IMU、GPS、回环进入同一GTSAM因子图
```

室内建图保持 `useGPS:false`，不启动ENU节点，但启用标准IMU因子。

## 2. 核心改造

### 2.1 建图服务互斥

- 原点锁定阶段允许暂时保留 `localization` 获取检查里程计。
- SLAM预热前必须执行 `full-stop`，关闭Nav2和定位节点。
- 启动前检查 `/localization`、Nav2生命周期节点和旧SLAM进程均不存在；未关闭成功则返回 `MAPPING_STACK_STOP_FAILED`。
- SLAM启动后检查 `/odom/localization_odom` 只有FAST-LIO-SAM一个发布者，防止双定位源和TF冲突。

### 2.2 专用ENU转换节点

- 在 `robot_slam` 增加 `slam_enu_converter` 节点：
  - 输入：`/fix`。
  - 输出：`/gnss/enu_odom`，类型为 `nav_msgs/Odometry`。
  - `frame_id=enu`，时间戳严格沿用 `/fix.header.stamp`。
  - 位置协方差从 `NavSatFix` 转换并保留，状态无效或数据过期时不发布有效ENU观测。
- 必填参数为 `lat0`、`lon0`、`alt0`；来源只能是本次锁定生成的 `gnss_origin.yaml`。
- 参数缺失、非有限、越界、三项全零、原点会话ID不匹配或文件校验失败时拒绝启动SLAM。
- Mapping Adapter生成本次启动专用参数文件；systemd建图单元改为启动包含ENU节点和FAST-LIO-SAM的统一launch。
- 室内模式不启动该节点，禁止复用上一次室外原点。

### 2.3 室外关键帧坐标

当前 `robot_slam/mapping` 已在 `<地图目录>/keyframes/keyframes.csv` 保存：

- `x/y/z/yaw`：雷达在 `map` 坐标系下的位姿，`yaw` 单位为弧度；
- `world_x/y/z` 和四元数：IMU/状态位姿；
- `lidar_x/y/z` 和四元数：完整雷达位姿；
- `rtk_latitude/longitude/altitude`、`rtk_heading_deg`：RTK位置和双天线航向。

现有 `x/y/yaw` 不是明确标识的原始ENU坐标。改造后，室外关键帧增加：

- `enu_x/enu_y/enu_z/enu_yaw`；
- `enu_valid`、`enu_origin_session_id`、`enu_origin_sha256`；
- ENU数据时间戳、数据年龄和位置/航向协方差。

`x/y/yaw` 继续保持现有含义，避免破坏旧地图、回环检测和救援脚本兼容性。

### 2.4 GPS和标准IMU因子图

- 增加明确配置：
  - 室外：`useGPS: true`、`useImuFactor: true`；
  - 室内：`useGPS: false`、`useImuFactor: true`。
- 正式建图关闭现有 `applyGnssCorrection` 直接改写FAST-LIO状态的路径，GPS仅通过GTSAM因子进入后端，避免重复融合。
- 因子图状态由单一 `Pose3` 扩展为每个关键帧的：
  - 位姿 `X(i)`；
  - 速度 `V(i)`；
  - IMU偏置 `B(i)`。
- 使用GTSAM `PreintegrationCombinedParams` 和 `CombinedImuFactor`：
  - 配置重力方向和大小；
  - 使用静止初始化获得初始姿态、速度和加速度计/陀螺仪偏置；
  - 使用真实IMU时间戳积分；
  - 加入偏置随机游走和完整预积分协方差；
  - `imu_gap`、时间回退或无效协方差区间不加入IMU因子并记录原因。
- 激光相邻关键帧因子、GPS位置因子、双天线航向因子、IMU预积分因子和回环因子加入同一张图。
- GPS因子读取 `/gnss/enu_odom`，保留杆臂补偿、RTK质量门控、协方差门控和Huber鲁棒核。
- 即使没有回环，只要存在有效IMU或GPS因子也执行图优化；回环不再是启动全局优化的前置条件。
- 扩展 `/slam/global_optimization_status` 和地图清单，记录各类因子数量、`useGPS`、`useImuFactor`、重力、初始偏置、原点哈希及优化前后误差。

### 2.5 建图完成后的回环检测与优化信息条

- 在停止建图后，将“回环检测与全局优化”设为地图保存和打包之间的独立可见阶段：

```text
保存原始地图
→ 扫描回环候选
→ 校验并接受/拒绝回环
→ 触发GTSAM全局优化
→ 重建点云、栅格和优化轨迹
→ 打包上传
```

- 地图管理页面增加单行主信息条，不能把回环优化过程笼统显示为“保存中”。信息条至少支持以下状态：
  - `等待触发`：原始地图尚未完成；
  - `检测中`：显示已扫描关键帧数量和候选回环数量；
  - `优化中`：显示已接受回环数量、因子总数和运行时间；
  - `重建地图中`：显示点云、栅格和轨迹重建进度；
  - `优化完成`：显示纠正量摘要和优化前后误差；
  - `无有效回环`：明确说明仍使用GPS、IMU和激光因子完成优化，或保持原始轨迹；
  - `已回退原始地图`：回环校验或优化失败时说明回退原因，不能显示为建图整体失败；
  - `优化失败`：仅在原始地图也不可用时阻止打包，并展示错误码和错误信息。
- 信息条必须展示触发依据和时间：触发来源、触发时间、检测耗时、优化耗时、地图重建耗时及数据更新时间（`x秒前`）。触发来源区分自动保存触发、人工重试和离线rosbag回放。
- 实时状态以 `/slam/global_optimization_status` 为主；完成后将同一份摘要持久化到 `map_manifest.json`、`mapping_trace.json` 和云端地图元数据，页面刷新、服务重启或上传完成后仍能恢复展示。
- `/slam/global_optimization_status` 扩展为可关联本次地图的结构化状态，至少包含：
  - `mapping_session_id`、地图目录、阶段、进度、更新时间和成功/回退状态；
  - 关键帧数、候选回环数、接受/拒绝回环数及拒绝原因统计；
  - 激光、GPS、双天线航向、IMU预积分和回环因子数量；
  - `error_before`、`error_after`、误差改善比例和优化迭代次数；
  - 原始轨迹、优化轨迹和最终地图实际采用的轨迹来源。

#### 2.5.1 位置和航向纠正展示

- 纠正量必须由同一关键帧的 `trajectory_raw.csv` 与 `trajectory_optimized.csv` 对齐计算，禁止使用不同时间或不同索引的样本直接相减。
- 对每个关键帧记录并可查询：
  - 原始 `x/y/z/yaw` 和优化后 `x/y/z/yaw`；
  - `delta_x/delta_y/delta_z`；
  - 平面位置纠正量 `sqrt(delta_x² + delta_y²)`；
  - 采用角度归一化到 `[-180°, 180°]` 后的 `delta_yaw_deg`；
  - 造成该段纠正的主要约束来源：回环、GPS、航向、IMU或组合约束。
- 信息条默认精简显示：

```text
回环优化完成 · 接受7/12个回环 · 平均位置纠正0.18m · 最大0.64m · 平均航向纠正1.7° · 最大5.2° · 图误差下降70.4%
```

- 展开详情后显示：平均值、RMS、P95、最大值及其关键帧编号；同时显示起点、终点和每个已接受回环两端的优化前后位置与航向差。
- 地图轨迹视图叠加原始轨迹与优化轨迹：原始轨迹使用虚线，优化轨迹使用实线；对纠正量超过阈值的关键帧绘制位移箭头和航向弧线。阈值默认位置 `0.30 m`、航向 `3°`，并允许配置。
- 室外地图额外展示 `map` 与ENU下的纠正量，确认优化没有破坏锁定的ENU原点和航向；若起点平移超过 `0.20 m` 或全局航向偏移超过 `2°`，显示醒目告警并禁止自动激活。
- 所有角度在接口中使用弧度，在页面中统一转换为度并明确标注；位置统一使用米。

## 3. 发散与救援地图

### 3.1 当前判定

- 位姿出现NaN/Inf：立即发散。
- 绝对Z超过5米：立即发散。
- 单帧位移超过1.5米、单帧Z跳变超过1米或速度超过3米/秒，连续3帧后发散。
- 连续10帧没有有效匹配点目前只标记为 `degraded`。
- 现有救援脚本按关键帧速度超过2米/秒或Z跳变超过0.2米截断；找不到异常时排除末尾5帧；剩余不足10个关键帧则救援失败。

### 3.2 改造后行为

- 每次健康检查记录 `last_healthy_keyframe`、触发指标、时间戳和发散原因。
- 发生 `SLAM_DIVERGED` 后立即停止关键帧采集和机器人运动，保留已经落盘的数据。
- 救援优先使用SLAM记录的最后健康关键帧；旧地图缺少该字段时才使用现有速度/Z启发式截断。
- 自动生成并上传标记为 `rescued_degraded` 的救援地图，但 `auto_activate=false`，必须人工检查点云、轨迹和原点后才能设为活动地图。
- GPS跳变、错误回环或优化失败只回退到原始轨迹，不直接把失败优化结果作为救援地图。

### 3.3 当前发散触发链路分析

- 健康检查在每个完成同步的激光帧中执行，顺序为：激光更新、ENU对齐采集、现有GNSS前端修正、`updateSlamHealth()`、地图增量和关键帧记录。配置扫描频率为10 Hz，因此健康检查通常约每0.1秒执行一次。
- IMU尚未完成静止初始化时只保持 `initializing`，不会触发位姿发散。
- 以下条件立即调用 `markSlamDiverged()`：
  - 位姿包含NaN或Inf；
  - 当前 `map` 位姿Z绝对值超过 `health_guard.max_abs_z=5.0 m`。
- 以下任一相邻帧异常会增加 `pose_anomaly_streak`，配置连续3帧后发散：
  - 三维单帧位移超过 `1.5 m`；
  - 单帧Z变化超过 `1.0 m`；
  - 按相邻帧时间差计算的速度超过 `3.0 m/s`。
- 连续10帧没有有效匹配点目前只进入 `degraded`，不会停止建图。
- `markSlamDiverged()` 当前只设置 `slam_diverged=true`、切换SLAM状态为 `ERROR`、写入失败进度并让主循环不再处理ACTIVE帧；它不会停止systemd进程、不会排空关键帧写盘队列，也不会直接让机器狗进入阻尼。
- Edge Agent按默认2秒周期读取 `save_progress.json`，发现 `SLAM_DIVERGED` 后只上传告警并播放“立即停止移动”的语音。用户随后点击保存时，保存服务拒绝正常地图导出，Adapter才进入现有救援脚本、停止SLAM、截断关键帧、打包并上传的路径。

当前判定还有两个必须修正的语义问题：

1. 发生单帧异常时，代码会把 `last_health_position` 和时间戳更新为该异常位姿。因此“连续3帧”实际要求每一对相邻帧都继续发生大位移；一次跳到错误位置后保持稳定，下一帧可能清零异常计数，错误地图不会被判定为最终发散。
2. 前端 `applyGnssCorrection()` 在健康检查之前直接修改状态，单次修正最大可达0.30 m。10 Hz附近的时间差会使换算速度接近或超过3 m/s；时间戳抖动或连续GNSS修正可能被误认为SLAM速度异常。必须先完成“GPS只进入后端因子图”的改造，再启用自动停止闭环。

### 3.4 是否直接自动停止SLAM

不采用“出现一次异常后立即 `systemctl stop`”的方案。按当前判定直接杀进程存在较高误停和数据损失风险：

- 室外坡道或累计高差超过5 m会触发绝对Z门限，即使轨迹连续且完全正常；室外不能继续使用固定的绝对Z门限。
- 激光匹配瞬时修正、激光时间戳抖动和现有GNSS前端修正都可能产生单帧速度尖峰。
- 当前析构路径调用 `stopKeyframeWriter(false)`，会清空尚未写完的关键帧队列；直接停止进程可能丢失最后一批健康关键帧和预积分文件。
- 进程停止后不能再通过现有服务完成写盘、状态快照和诊断收尾，救援只能依赖不完整目录。

改为四级状态机：

```text
HEALTHY
  → DEGRADED（单次异常或匹配质量下降，只告警并拒绝异常帧）
  → SAFE_HOLD（异常达到确认门限，停止采集和机器狗运动，但保留SLAM进程）
  → DIVERGED（证据落盘并确认不可恢复，自动生成救援地图）
  → PROCESS_STOPPED（写盘和诊断收尾完成后才停止systemd进程）
```

处理原则：

- NaN/Inf、状态协方差非有限、关键帧写盘不可恢复错误属于 `fatal`，立即进入 `SAFE_HOLD`，无需等待3帧。
- 位移、速度、Z跳变属于 `suspected`。第1帧起就拒绝本帧状态，不允许执行 `map_incremental()` 和关键帧记录；连续3帧或5帧窗口内达到3次后进入 `SAFE_HOLD`。
- 异常比较基准始终使用最后接受的健康位姿，异常帧不得覆盖基准。这样既能识别“跳到错误位置后保持不动”，也不会把被拒绝的瞬时修正写进地图。
- 室内可保留相对起点高度保护；室外关闭固定绝对Z门限，改用单帧Z跳变、垂直速度、轨迹坡度和里程计/IMU一致性联合判定。
- RTK跳变、GPS中断、水平误差变差只拒绝GPS因子，不判定SLAM发散。错误回环或图优化失败只回退原始LIO轨迹。
- 连续无有效匹配点分级处理：10帧为 `DEGRADED`；达到可配置的更长窗口并且IMU/里程计也不能维持可信预测时才进入 `SAFE_HOLD`。

### 3.5 SAFE_HOLD与自动救援执行顺序

进入 `SAFE_HOLD` 后必须按以下顺序执行，不能先杀SLAM：

1. 原子关闭 `mapping_capture_enabled`，状态切换为 `SAFE_HOLD`，拒绝当前异常状态并停止地图增量和关键帧生成。
2. 通过统一遥控桥发送 `passive`，同时清零速度命令；控制确认失败时持续重试并发布高优先级告警。该动作由SLAM即时事件或本机IPC触发，不能只依赖Edge的2秒状态轮询。
3. 记录并原子写入 `divergence_event.json`，至少包含：
   - `last_healthy_keyframe`、最后健康位姿和时间戳；
   - 触发类型、触发值、配置阈值、连续次数；
   - 当前激光/IMU/RTK/里程计时间戳和数据年龄；
   - 异常前预测位姿、被拒绝位姿、位置和航向差；
   - 关键帧写盘队列长度、已写数量和诊断rosbag目录。
4. 调用带超时的 `flushKeyframeWriter()`，确保最后健康关键帧、扫描PCD和IMU预积分文件全部落盘；失败时保留明确的写盘错误和最后成功索引。
5. 诊断rosbag在事件后继续录制可配置的3至5秒，再正常发送SIGINT关闭，保留异常前后完整数据。
6. 救援脚本优先按 `last_healthy_keyframe` 截断；仅旧地图没有该字段时使用速度/Z启发式。室外救援禁止把所有Z强制归一化到首帧高度。
7. 生成 `rescued_degraded` 地图并上传，固定 `auto_activate=false`；地图、轨迹、ENU原点和诊断数据完备后，最后停止 `roamerx-mapping.service`。

只允许在“单帧异常被拒绝、之后连续健康、地图和关键帧均未被污染”的情况下由操作员确认恢复；已经进入 `DIVERGED` 或发生NaN/Inf时禁止自动续建，必须结束本次会话并检查救援地图。

### 3.6 误停风险结论与验收门限

- 如果直接沿用当前条件自动杀进程，室内一般不会频繁中断，但室外高差、时间戳抖动和GNSS前端修正会带来不可接受的误停风险。
- 采用“异常帧拒绝 + 3/5窗口确认 + SAFE_HOLD排空写盘 + 最后停进程”后，正常单帧匹配抖动不会中断会话；真正持续发散仍能在约0.3至0.5秒内停止地图污染，并尽快让机器狗进入阻尼。
- 上线前必须用rosbag注入以下场景并统计误触发率：单帧0.3/1.0/1.6 m跳变、持续位姿漂移、时间戳抖动、短时无点云、室内楼梯、室外超过5 m高差、RTK跳变、GNSS中断和真实快速转向。
- 验收要求：单帧瞬时异常只拒绝该帧且不增加关键帧；持续异常可靠进入SAFE_HOLD；正常室内和室外回放均不得误停；发散后最后健康关键帧及其全部预积分文件必须存在于救援ZIP中。

### 3.7 发散救援实现任务拆分

1. 将 `updateSlamHealth()` 从无返回值改为返回 `ACCEPT/REJECT_FRAME/SAFE_HOLD/FATAL` 判定，并保留激光更新前的可信状态用于回滚。
2. 新增 `last_healthy_keyframe` 和 `divergence_event.json` 持久化；健康基准只在帧被接受后更新。
3. 新增SLAM侧 `SAFE_HOLD` 状态和“停止采集、排空写盘、事件通知”服务/话题。
4. Edge接收即时事件后调用统一遥控桥 `passive`，停止rosbag并自动执行救援，不再等待人工点击保存。
5. 修改救援脚本优先使用明确截断点，保持室外真实Z，并兼容没有新字段的旧地图。
6. 增加状态机、异常帧回滚、写盘排空、自动阻尼、自动救援、禁止激活和进程重启恢复测试。
