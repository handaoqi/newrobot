# 室内 FAST-LIO2、NDT/VGICP 循环导航与重定位完善计划

## 1. 目标

- FAST-LIO2 继续作为唯一连续主定位源，保持约 10 Hz 平滑里程计。
- NDT/VGICP 只作为地图绝对校正与健康检查，不连续驱动 UKF，不造成 `map-odom` 频繁跳变。
- 降低短时 NDT 退化造成的误停车，同时确保真正定位丢失时立即停车。
- 补齐 FAST-LIO2 断流、进程退出、较大航向误差和较大位置偏移后的自动恢复闭环。
- 建立室内循环导航的量化验收方法，区分“经过航点”和“精确到点”。

## 2. 当前实现基线

### 2.1 FAST-LIO2 主定位

- 导航阶段以 `robot_slam/mapping` 的 `frontend.odometry_only=true` 模式运行。
- 输入 `/front_lidar` 和雷达内置 `/front_lidar/imu`，输出 `/odom/lio_odom`。
- 室内点云范围为 0.5-10 m，导航前端使用 360° 点云并开启重力约束地面滤除。
- FAST-LIO2 内部使用激光-IMU紧耦合 ESKF；定位 UKF 设置 `use_imu=false`，不重复融合原始 IMU。
- 导航阶段关闭 FAST-LIO2 后端回环、GNSS因子、地图输出和全局优化。

### 2.2 NDT/VGICP 地图校正

- NDT使用全局 PCD 粗配准，分辨率0.15 m，正常接受分数上限0.50。
- 稳定阶段同时受 stride 和单调时钟限制，最高2 Hz；初始化/恢复最高5 Hz。
- 高质量NDT分数低于0.30时跳过VGICP；其他情况在当前位置周围18 m局部地图执行FastVGICP。
- VGICP只有在分数至少改善5%，且与NDT相差不超过0.30 m、5°时才可替代NDT。
- LIO与地图偏差达到0.30 m或5°、连续3个稳定样本且不存在大跳变时，才排队执行一次校正。
- 校正按0.25 m/s和8°/s平滑施加；两次校正至少间隔3秒，完成后继续屏蔽3秒。
- 匹配质量用于动态协方差，边界质量匹配不会获得与高质量匹配相同的UKF权重。

### 2.3 当前地图与导航限制

- 当前激活室内地图有76个关键帧、380个回环候选、0个通过回环。
- 离线惯性平滑候选被质量门拒绝，当前恢复并使用原始FAST-LIO2地图。
- 候选相对原始轨迹末端修正约0.17 m、1.07°；拒绝原因是相邻XY修正0.15526 m略高于0.15 m门限。
- 普通巡检航点位置容差为0.35 m，普通中间航点不强制航向，因此当前语义是“稳定经过航点”，不是“每圈精确停在同一位置和航向”。

## 3. 当前定位丢失恢复链

### 3.1 定位节点内部恢复

- FAST-LIO单帧位移大于1.5 m、航向跳变大于12°或航向速度超过60°/s时，锁存运动异常。
- 异常期间保持最后可信位姿、清零速度并发布状态4，不把机器人位姿拉回地图原点。
- 无可用绝对位姿达到10帧后，使用最后可信位姿触发一次后台全局ICP；失败后每5秒允许重试。
- 初始化和恢复需要连续2次NDT匹配分数低于0.50。

### 3.2 任务层恢复

- 连续5个定位状态不是3，或连续3次NDT不健康，触发任务级恢复。
- 先取消Nav2目标、下发零速度并暂停任务。
- 优先读取内存中的最后可信位姿，其次读取持久化可信位姿。
- 静止测试12个候选：原位置8个航向以及前后左右各1 m的位置候选。
- 候选必须获得连续3个正常状态样本，并且绝对定位稳定。
- 恢复后继续原来的待执行航点，不按最近距离重新选择航点，避免循环路线跳段。
- 当前12个候选全部失败后只会按恢复周期继续重试最近可信位置，尚未执行真正不依赖最近位置的全图候选检索。

## 4. 已确认风险

1. NDT最高2 Hz时，连续3次失败约1-1.5秒就会暂停任务；动态人员、玻璃或短暂无特征区域可能造成频繁误中断。
2. FAST-LIO仍健康时，NDT退化应视为绝对地图约束退化，不应立即等同于连续主定位丢失。
3. FAST-LIO进程退出或 `/odom/lio_odom` 断流时，重复发布 `/initialpose` 无法恢复，必须先重启定位与LIO。
4. Scan Context运行模式仍为 `disabled`，当前恢复高度依赖最后可信位置；机器人被搬动较远或最近可信位置本身错误时不能保证恢复，也没有“局部恢复失败后仅执行一次”的全局无初值兜底。
5. 静止候选搜索不会命令机器人旋转，安全性高，但当前位置视野不足时可能长期失败。
6. 当前地图没有已接受回环，不具备长期循环地图一致性的直接证据。
7. NDT健康判定最低内点率为5%，对重复走廊可能偏宽松，需要用真实数据分布校准。

## 5. 第一阶段：区分NDT退化与主定位丢失

- 保留以下立即停车条件：定位状态4、FAST-LIO时间超时、FAST-LIO运动异常、位姿非有限、定位进程退出。
- FAST-LIO健康且连续输出时，将NDT退化划分为三级：
  - 连续3次失败：进入 `ndt_degraded_warning`，上报告警但不重定位；
  - 连续5秒或10次失败：降低任务速度上限到0.15 m/s，等待地图匹配恢复；
  - 连续10秒或20次失败，或同时检测到LIO/map创新持续扩大：停车并进入重定位。
- NDT连续3次健康后清除退化状态并恢复正常巡检速度。
- RTK/UKF策略下，如果固定RTK已是有效辅助校正源，继续忽略未被当前策略采用的NDT退化。
- 将次数和时间同时参数化，避免修改NDT频率后改变实际触发时间。

建议参数：

```yaml
safety:
  ndt_warning_samples: 3
  ndt_slowdown_seconds: 5.0
  ndt_relocalize_seconds: 10.0
  ndt_recovery_samples: 3
  ndt_degraded_speed_mps: 0.15
```

## 6. 第二阶段：补齐FAST-LIO断流自动重启

- 在任务恢复前读取 `/localization/decision`，区分：
  - `lio_imu`健康但NDT退化；
  - LIO时间超时；
  - LIO运动异常锁存；
  - 定位节点或LIO进程退出。
- 如果LIO断流或进程退出，恢复顺序固定为：
  1. 保持Nav2目标取消和零速度；
  2. 调用 `start_navigation_real.sh restart-localization`；
  3. 等待定位节点、地图加载服务和 `/odom/lio_odom` 恢复；
  4. 重新加载当前激活PCD；
  5. 发布最后可信位姿；
  6. 要求连续3个状态3且 `absolute_stable=true`；
  7. 等待稳定3秒后恢复原航点。
- 每个恢复周期最多重启一次定位，两个重启周期至少间隔30秒，避免反复拉起进程。
- 连续失败次数参数化；达到上限后保持停车并升级人工告警。默认可继续无限等待，但不得无限频繁重启。
- 增加恢复阶段、失败原因、LIO年龄、进程PID、地图版本和候选序号诊断。

## 7. 第三阶段：局部恢复失败后的单次全局无初值重定位

### 7.1 “无初值”的定义

- 不能把单位矩阵或地图原点直接送给全图ICP并称为无初值重定位；ICP仍需要落在正确收敛域，在重复走廊中还可能形成高分错误匹配。
- 本计划的无初值重定位是：不使用最近可信XY和航向作为搜索中心，使用当前扫描的Scan Context描述子在全部地图关键帧中检索位置和360°航向假设，再用真实点云几何配准决定是否接受。
- 当前地图已有关键帧、Scan Context和描述子文件，可作为全局候选库；缺失或校验失败时禁止降级为盲目的全地图栅格ICP搜索。

### 7.2 触发顺序和一次性锁

- 只有同时满足以下条件才触发：
  1. Nav2目标已经取消、`cmd_vel`已经归零、任务处于定位暂停状态；
  2. FAST-LIO和定位进程仍存活，或已按第6节完成一次重启；
  3. 最近可信位置的8个航向和前后左右±1 m共12个候选全部失败；
  4. 当前地图版本与可信位置所属地图版本一致；
  5. 当前扫描点数、时间戳和传感器健康满足重定位要求。
- 每个定位丢失事件只允许执行一次全局无初值任务，使用 `loss_episode_id + global_attempted` 锁存；普通5秒或30秒重试不得重复触发。
- 收到新的人工初始位姿、切换地图、重新启动任务或形成新的可信位姿后，才清除一次性锁。
- 全局任务运行期间暂停局部候选重试，使用generation编号丢弃旧任务或旧地图产生的迟到结果。

建议参数：

```yaml
relocalization:
  no_initial_global_once:
    enable: false
    trigger_after_local_candidates_exhausted: true
    max_attempts_per_loss_episode: 1
    timeout_seconds: 15.0
    top_k: 5
    max_geometric_candidates: 3
    validation_frames: 3
```

`enable`在shadow回归完成前保持false；验证通过后，才允许地图管理或部署策略开启。

### 7.3 全局候选生成与几何验证

- 对当前去地面、裁剪后的扫描生成Scan Context描述子，检索全地图Top-K关键帧及其循环移位航向。
- 对候选按描述子距离、关键帧可用性和空间去重排序；相邻关键帧只保留一个，避免把计算预算浪费在同一地点。
- 最多对3个候选执行粗到精几何验证：
  1. 以关键帧XY和Scan Context航向建立候选位姿；
  2. 在候选周围裁取局部地图，执行低分辨率粗配准；
  3. 粗配准通过后执行NDT/FastVGICP精配准；
  4. 计算RMSE、内点数、双向重叠率、NDT/VGICP一致性、Hessian退化方向和最终位姿差异。
- 单次全局任务总墙钟时间不超过15秒，后台容量保持1；超时、地图切换或新人工位姿到达时立即丢弃结果。
- 基础几何硬门沿用：内点不少于500、双向重叠率不低于0.45、RMSE不高于0.25 m；重复走廊等退化场景还必须通过NDT/VGICP一致性和Hessian门。
- 如果前两名候选几何质量接近但位置相距明显，判定为场景歧义，不写入任何候选。

### 7.4 候选写入后的二次确认

- 几何通过不直接恢复任务；定位节点先原子重置map-LIO锚点和UKF，不从旧位置平滑跨越到新位置。
- 使用随后连续3帧独立扫描重新执行局部NDT/VGICP，要求：
  - 三帧均收敛且分数低于正常接受门限；
  - 三帧位置离散不超过0.20 m、航向离散不超过3°；
  - FAST-LIO运动连续，`absolute_stable=true`；
  - 不存在超过1 m的首次确认跳变或NDT/VGICP冲突。
- 二次确认通过后发布状态3，再等待稳定3秒并继续原待执行航点。
- 任一确认失败都撤销候选，恢复最后可信位姿的保持状态；不得用失败候选更新可信位置数据库。

### 7.5 全局一次失败后的处置

- 全局候选为空、全部几何失败、候选歧义、超时或二次确认失败，都将本次事件标记为 `global_no_initial_failed`。
- 保持机器人停车和任务暂停，禁止在同一丢失事件中再次自动全局搜索。
- 可继续低频尝试最近可信位置的局部恢复，但不能恢复运动，直到局部验证成功、操作员设置初始位姿或重新启动任务。
- 上报严重告警，包含地图版本、局部12候选结果、Top-K描述子、几何拒绝原因、总耗时和rosbag路径。

### 7.6 Scan Context启用步骤

- 首先将 `relocalization.scan_context_runtime_mode` 从 `disabled` 切换为 `shadow`。
- shadow模式执行完整的全图检索、真实几何验证和连续多帧复核，但不改变机器人位姿。
- 每次事件保存：真实位置、候选关键帧、航向偏移、描述子距离、ICP/GICP RMSE、双向重叠率、内点数、候选歧义和最终是否正确。
- 验收达到以下条件后才能开启 `no_initial_global_once.enable`：
  - Top-K正确召回率不低于95%；
  - 错误候选几何通过率不高于1%；
  - 正确候选最终重定位成功率不低于95%；
  - 错误位姿写入次数为0。
- 常规运行仍不允许每次NDT失败调用全局搜索；该能力只作为局部12候选全部失败后的单次兜底。

## 8. 第四阶段：地图回环审核与激活

- 对当前380个回环候选在地图管理中展示候选端点、相距时间、描述子分数、几何重叠、RMSE和预测位姿修正。
- 人工确认后才执行离线因子图优化；自动应用默认保持关闭。
- 优化输出必须保留原始地图、候选地图和审核报告，不覆盖原图。
- 激活优化地图前执行：
  - 相邻关键帧位姿连续性检查；
  - 起点、终点和主要交叉口局部点云一致性检查；
  - 关键帧留一法NDT/VGICP定位检查；
  - 至少5个已知位置的冷启动初始化检查；
  - 原始地图与优化地图的PGM障碍拓扑差异检查。
- 若只因边界值拒绝，例如0.15526 m对0.15 m，不能直接放宽门限；先检查异常关键帧、IMU预积分和局部点云，再决定剔除关键帧或调整阈值。

## 9. 第五阶段：精确循环导航策略

- 普通巡检点继续允许0.35 m通过式容差，避免每个点停车旋转。
- 对门口、设备检查点、充电预停点增加“精确航点”属性：
  - XY容差0.15-0.20 m；
  - 航向容差5-10°；
  - 要求NDT或其他绝对校正源健康；
  - 到点前降低速度到0.10-0.15 m/s。
- 回充最终对接继续使用独立近场传感器和对接状态机，不能仅依赖0.08 m地图定位容差。
- 记录每圈的横向误差、航点误差、终点闭合误差、NDT成功率、校正次数和重定位次数。

## 10. 测试计划

### 10.1 单元与回放测试

- NDT 3次失败只告警、5秒降速、10秒停车。
- NDT恢复3次后解除降速。
- LIO状态正常时NDT短时失败不得重启定位。
- LIO断流、进程退出和运动异常分别进入正确恢复分支。
- 重启后必须等待新PID、新LIO数据、地图加载和绝对稳定，禁止使用旧ROS图节点误判成功。
- 候选搜索覆盖8个航向和±1 m位置，验证失败不恢复任务。
- 12个局部候选未全部失败时不得触发全局无初值任务。
- 同一 `loss_episode_id` 最多触发一次全局任务；周期重试、迟到结果和重复回调不得绕过锁存。
- 全局Top-K候选覆盖正确召回、无候选、几何拒绝、重复走廊歧义、超时、地图切换和generation失效。
- 几何候选通过后必须再通过连续3帧局部验证；任一帧失败都不得发布恢复成功。
- 全局失败后保持停车和暂停，不更新最后可信位姿；人工初始位姿或新任务才能重新授权一次全局尝试。
- 恢复后保持原 `current_waypoint_index`，循环路线不得跳到返程重复点。

### 10.2 实机循环测试

- 同一室内路线连续运行不少于20圈或2小时。
- 覆盖长走廊、转角、玻璃、动态人员、原地转向和窄门。
- 人为遮挡雷达、暂停LIO进程、制造短时NDT失败，验证停车和恢复顺序。
- 在已知关键帧附近测试±1 m、±45°、±90°、180°重定位。
- Scan Context shadow阶段增加跨房间搬动、相似走廊、反向放置和最近可信位置故意错误测试，但禁止自动写入候选位姿。
- active验收时人为让12个局部候选全部失败，确认只执行一次全局搜索；成功后继续原航点，失败后持续停车。

## 11. 验收标准

- FAST-LIO和定位里程计频率不低于8 Hz；稳定NDT/VGICP不超过2.1 Hz。
- 正常循环期间定位状态3占比不低于99.9%，无错误地图跳变。
- 普通路线横向误差P95不超过0.20 m，精确航点误差P95不超过0.20 m。
- 每圈回到起点的位置差P95不超过0.15 m、航向差P95不超过3°。
- 短于5秒的NDT退化不暂停任务；真正LIO丢失后0.5秒内停止运动。
- LIO断流恢复成功率不低于95%，成功恢复后等待稳定3秒再继续任务。
- 最后可信位姿候选重定位成功率不低于95%；错误候选不得恢复运动。
- 局部恢复失败后，每个丢失事件全局无初值搜索最多执行一次，任务超时不超过15秒。
- 全局无初值正确候选最终恢复成功率不低于95%，重复走廊歧义必须拒绝，错误位姿写入次数为0。
- 连续20圈无自主任务跳段、无频繁校正蛇形、无服务崩溃或RSS持续增长。
- Scan Context在shadow数据达到门限前保持关闭写入；active阶段错误位姿写入次数必须为0。

## 12. 实施顺序

1. 增加NDT退化分级与时间迟滞，先解决误停车。
2. 增加LIO断流诊断和定位重启闭环。
3. 完成回放测试和20圈室内循环基线。
4. 启用Scan Context shadow并收集真实候选数据。
5. 实现 `loss_episode_id`、单次全局任务和连续3帧二次确认，但保持位姿写入关闭。
6. 审核当前地图回环候选，生成但不自动激活优化地图。
7. 通过地图自检、shadow回归和实机搬动验收后，只开启“局部恢复失败后的单次全局写入”。

## 13. 默认安全原则

- FAST-LIO2始终是唯一连续主定位源。
- NDT、VGICP和RTK只能间断校正，不得连续驱动UKF。
- 定位状态4、LIO断流或异常跳变立即停车。
- 不以单次NDT失败触发位姿重置。
- 重定位成功前不恢复Nav2目标。
- 全局无初值重定位只能在局部12候选全部失败后执行，每个定位丢失事件最多一次。
- 全局候选必须通过几何硬门和连续3帧二次确认；候选歧义一律拒绝。
- 自动回环优化和Scan Context位姿写入默认关闭，必须经过地图审核和实机验证。
