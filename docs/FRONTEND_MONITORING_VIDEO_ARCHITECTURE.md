# 前端监测中心与视频链路架构

更新时间：2026-08-24

## 1. 页面加载分层

```text
路由进入
  └─ 立即渲染页面骨架、摘要占位、卡片和操作区域
       └─ 异步读取 overview / robot / task 数据
            └─ 获取 play_urls 后连接 FLV/HLS
                 ├─ 连接中：正在加载视频流
                 ├─ 成功：显示视频与实时叠加层
                 └─ 失败：显示无信号/错误提示，其他功能继续可用
```

监测中心在页面级管理检测框、接管、告警 SSE 和音频状态；保安值守通过 `LiveVideoPlayer` 管理直播、回放、收音和播放器销毁。视频状态不能反向阻塞任务状态、地图和告警列表。

工作台页面通过 `src/router/index.js` 统一挂载在 `DashboardLayout.vue` 下。除监测中心和保安值守外，统计、事件、机器人、巡检任务、日历、执行详情、地图、路线、禁区、轨迹和远程开发页面均复用同一鉴权、主题切换、用户信息和退出登录边界。页面数据请求统一经过 `src/services/api.js`，不在 view 中创建第二套鉴权或 HTTP 封装。

响应式显示也由 `DashboardLayout.vue` 统一提供。在 `641–1024px` 竖屏视口，侧栏折叠为顶部应用栏和抽屉导航；路由标题、用户操作和主题切换仍保留在工作台壳层。页面主体取消桌面整体缩放，按内容优先级改为单列或局部双列，纵向滚动由页面承载，禁止无意的全局横向滚动。

监测中心、保安值守和远程控制共享一个 `SharedLiveVideoHost`。各页面只把视频槽位放在自己的布局中，并通过 `useSharedVideoStream` 写入机器人、播放地址、可用性和 `objectFit`；页面切换时共享宿主清理视频源，避免多个 `LiveVideoPlayer` 同时占用媒体资源。

## 2. 播放器接口

| 属性 | 作用 |
| --- | --- |
| `playUrls` | 当前机器人 FLV/HLS 地址 |
| `robotId` | 音频采集命令目标 |
| `available` | 是否存在可播放地址 |
| `loading` | 页面数据仍在加载时保持加载提示 |
| `objectFit` | 视频填充策略 |

播放器在 source、机器人或可用性变化时销毁旧实例后重建；组件卸载时释放 HLS、MPEG-TS、历史清单 URL 和直播守护定时器。

## 3. 失败处理与主题

- 自动播放被拒绝时保留视频元素和可操作控件。
- FLV/HLS fatal error 触发无信号态和 `stream-error` 事件。
- 监测中心继续显示摘要、事件和控制卡片；保安值守继续显示任务、定位和地图。
- 视频加载态使用深色视频背景和高对比文字；宽屏优先保证视频区域，窄屏按单列排列。
- 平板竖屏不使用整体 `zoom` 压缩：视频区域按 `16 / 9` 等可读比例布局，底部信息、告警技能、任务控制和状态卡片允许换行；主要按钮、菜单和输入控件至少为 `44×44px`。
- 平板首批视觉回归覆盖登录、监测中心、保安值守和远程控制；三档视口为 `768×1024` WebKit、`800×1280` Chromium、`834×1194` WebKit。

## 4. 生命周期与验收边界

- `LiveVideoPlayer` 在播放地址、机器人或可用性变化时先销毁旧播放器，再创建新实例；组件卸载时释放播放器、媒体元素、Object URL、定时器和事件监听器。
- 监测中心的告警 SSE、检测框刷新和远程控制状态属于页面级状态；离开页面后必须停止连接和轮询，不能由后台残留请求继续改变已卸载页面。
- 地图和路径规划页面分别清理建图状态轮询、导航状态轮询、窗口 resize 监听和路线演练动画；地图交互失败只显示页面错误，不应清除已编辑的路线或途经点。
- 最小手工验收包括：浅色/深色主题、宽窄屏布局、视频无地址和播放失败、刷新/离开页面后的资源清理，以及无后端或媒体环境时其他卡片仍可用。

### 4.1 平板自动化验收

`tests/tablet/tablet-portrait.spec.js` 使用 `tests/tablet/mock-api.js` 的固定数据，不依赖 Django、媒体服务或真实机器人。每个页面会生成首屏基线、全页截图和 JSON 布局报告，并检查：

- 页面及可见元素不越出视口，文档不产生非预期横向滚动；
- 主要按钮、菜单、输入、选择框和文本域不小于 `44×44px`；
- 平板抽屉可以由菜单按钮打开、由 Esc 关闭，并在关闭后恢复按钮焦点；
- 截图与已审核基线一致。

本地流程为 `npm run tablet:capture` → AI/人工查看 `test-results/tablet/` → 修改布局 → `npm run test:tablet`。只有确认视觉变化符合预期后才执行 `npm run test:tablet:update` 更新 `tests/tablet/__screenshots__/`。GitHub Actions 还会执行单测、生产构建并上传失败报告。
