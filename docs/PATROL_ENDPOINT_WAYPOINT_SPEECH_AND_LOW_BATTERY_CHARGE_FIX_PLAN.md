# 巡检终点、节点状态、到点播报与低电量在桩充电修复计划

## 1. 目标

统一修复并验证以下四条相互关联的任务闭环：

1. Nav2 报告巡检成功后，终点复核不再因机器狗停车余量误报 `FINAL_POSE_OUT_OF_TOLERANCE`，但仍保留真实偏离检查。
2. 保安值守页面按实际执行顺序显示节点状态：未下发为蓝色、当前目标为黄色、确认到达为绿色；往返路线中的重复地图点不能串色。
3. 每个到达节点只触发自己的播报，播报完成后才下发下一段；终点播报期间发生定位恢复时不得重复下发终点。
4. 电量低于 20% 时仍维持“一次低电量事件只触发一次回充动作”。若已经在充电桩上，则不再创建返航任务，必须在 5 分钟内自动尝试一次开始充电。

## 3. 修复设计

### 3.1 巡检终点

终点成功采用固定顺序：

1. Nav2 返回成功且没有 missed waypoint。
2. 下发零速度并等待机器人速度低于停止阈值持续 1 秒。
3. 读取采样时间不超过 1 秒且 `absolute_stable=true` 的绝对定位。
4. 普通巡检按 `0.45 m` 复核；充电桩末端继续使用 `0.08 m` 和现有航向容差。
5. 复核通过后发布终点 `waypoint_reached`，执行到点播报；播报完成后再次确认机器人仍停止，再完成任务。

不继续放大容差。超过 0.45 m 时保留 `FINAL_POSE_OUT_OF_TOLERANCE`，并在错误详情中附带目标坐标、实测坐标、定位采样时间和定位源，便于区分控制器提前判到、停车余量和定位跳变。

### 3.2 节点状态

以 `execution_waypoint_index` 作为唯一执行位置，`waypoint_id` 仅作兼容回退：

- `task.target_dispatched`：对应执行节点变黄色；清除其他仍为黄色但没有后续到达事件的陈旧目标显示，不伪造绿色到达。
- `task.waypoint_reached`：同一执行节点由黄色变绿色。
- 未收到目标事件的节点保持蓝色。
- 事件按 `state_version` 排序和去重；旧版本事件不得覆盖新状态。
- 页面刷新后从持久化的节点里程碑重建状态，不使用任务对象中单一的 `current_waypoint_index` 推测历史节点。

Edge 对批量 FollowWaypoints 的反馈必须继续补齐跨过节点的“到达旧节点 → 下发新节点”事件对，确保第 2、3 个点也有独立状态，不只显示第一个目标过程。

### 3.3 到点播报

- 平台仅在持久化成功的 `task.waypoint_reached` 上创建播报命令，幂等键为 `任务执行 ID + execution_waypoint_index`。
- 命令必须携带对应节点的 `waypoint_id`、执行序号和模板；设备状态文件继续使用 `任务执行 ID/节点哈希.json`，写入采用临时文件原子替换。
- Edge 在状态为 `finished` 前不下发下一导航段；`failed/superseded/timeout` 使用现有明确失败码结束任务。
- 定位在播报等待期间丢失时，只停车并保留 `_speech_waiting_index`，不取消已经完成的 Nav2 goal。
- 定位恢复时：
  - 播报仍在进行：恢复任务状态但继续等待，不重新下发该节点。
  - 播报已经完成：直接执行该节点之后的续跑或终点完成逻辑。
- 增加第 1、2、3 点分别播报、往返重复点、终点播报中定位丢失/恢复、Edge 重复收到平台事件等测试。

### 3.4 低于 20% 且已经在充电桩上

#### 判定

电量必须严格 `< 20%` 且连续两个有效样本。满足以下任一条件视为“已经在桩上”：

- ARC：`arc_dock_contact=true`、`arc_dock_state in {1, 2}` 且 `arc_dock_error` 为空；
- legacy：蓝牙已连接、充电引脚和正负极接触均为 1。

若 BMS 已有有效充电电流，直接把本次 episode 标记为已满足，不再下发启动命令。

#### 单次启动窗口

- 创建低电量 episode 时写入 `triggered_at_epoch` 和 `dock_charge_deadline_epoch = triggered_at + 300s`。
- 已在桩但尚未充电时，优先走本地 `charge.start`，不取消/创建导航返航任务；正常情况下立即执行，因此满足 5 分钟内要求。
- 一个 episode 只允许一次实际启动尝试。调用前原子持久化 `dock_charge_attempt_state=starting` 和时间，避免遥测线程、到桩回调及 Edge 重启后重复执行。
- 成功后记录 `started`；失败记录 `failed`、错误码和错误信息，并告警人工检查，不自动移动机器人、不进行第二次尝试。
- Edge 重启后若 episode 仍有效、已经在桩、尚未尝试且未超过 300 秒，恢复这一次启动尝试；超过窗口则记录 `expired`，不迟到补发。
- 若不在桩，保持原来的一次性返航事件和回充任务；到桩任务自己的 `docking_arrived_handler` 负责开始充电，不额外消费“已在桩直启”次数。
- 手动断开充电后的 300 秒抑制策略继续生效，优先级高于自动直启。

#### 平台协同

低电量告警增加 `action`：

- `charge_start_attempted_on_dock`
- `already_charging_on_dock`
- `return_charge_requested`
- `charge_start_failed_on_dock`

平台仅对 `return_charge_requested` 创建返航任务；其余在桩状态只入库、播报和展示结果，禁止再次下发返航路线。

## 4. 测试与验收

### 自动测试

- 终点距离 0.42 m 成功、0.46 m 失败；定位过期或非绝对稳定时不得完成任务。
- 三点及往返 `1-2-3-2-1` 路线产生完整、按序、互不串色的目标和到达事件。
- 每个点只生成一次对应播报；播报未完成不下发下一段；终点播报中定位恢复不增加 Nav2 goal 数量。
- 低电量边界：20% 不触发、19% 连续两个样本触发、25% 重置 episode。
- 19% 已在桩：300 秒窗口内只调用一次 `charge.start`，平台不创建返航任务。
- 已在充电、启动失败、Edge 重启恢复、超过 300 秒、手动断开抑制、遥测和到桩回调并发均不得重复启动。

### 真机验收

1. 执行原三点路线，确认节点依次蓝 → 黄 → 绿，且只有当前目标为黄色。
2. 为三个点配置不同文案，确认实际按 1、2、3 点分别播报，播报结束后才继续。
3. 在终点播报期间制造一次可恢复的短时定位中断，确认终点不重复下发、任务最终只完成一次。
4. 使用低电量模拟输入并保持机器已在桩，确认 5 分钟内出现且仅出现一次充电启动生命周期；后台无新返航任务。
5. 启动失败时确认机器人保持静止、产生告警且不会循环重试。
