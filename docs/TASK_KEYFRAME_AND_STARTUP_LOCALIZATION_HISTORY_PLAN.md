# 任务关键帧与任务启动定位历史回放

## 目标

路径规划页在“建图关键帧”下方显示当前路线最近一次（可切换历史）任务的关键帧。表格字段、分页和地图点选与建图关键帧一致：序号、采样时间、NDT x/y/yaw、RTK x/y/yaw/状态。

“定位尝试过程”不移动，继续位于导航状态机上方；实时初始化、主动重定位与历史任务启动初始化均在该卡片展示。

## 已确认的缺陷

任务启动的定位过程经 `task.start` 的 `command.progress` 上报。后端已将其作为定位进度深度合并保存，但路径规划页只从导航状态接口的 `localization_command` 恢复；该接口只选择 `nav.initial_pose` 和 `nav.relocalize`。任务详情加载后也没有使用 `taskMapExecution.commands` 回填卡片，因此刷新页面或选择历史任务后看不到任务启动的初始化过程。

## 实施

1. 任务详情加载后选择本任务的 `task.start` 命令，优先使用深度合并的定位结果；若结果缺失，再按命令进度事件顺序恢复候选阶段。地图和版本必须一致。
2. 实时 `nav.initial_pose` / `nav.relocalize` 正在执行时具有更高优先级，历史任务不得覆盖；没有任何历史进度时明确提示，不伪造结果。
3. 扩展任务轨迹批次，在 accepted 启动初始化、运行和暂停定位恢复等非终态阶段记录紧凑关键帧。每帧只保存 NDT/RTK 显示字段、定位源、任务状态和航点序号，不上传重复完整遥测。
4. 后端以可选字段兼容旧 Edge 和旧数据；旧任务缺少 NDT/RTK 时显示“旧任务未采集 NDT/RTK 关键帧”。
5. 已结束任务的关键帧保留 14 天；活动任务不参与清理。

## 验收

- 选择历史“2号地图-RTK路线1”任务时，导航状态机上方能显示中心已收到的 `task.start` 初始化候选过程。
- 新任务的任务关键帧表与建图关键帧列和交互一致，启动初始化阶段也有数据。
- 实时定位操作不被历史记录覆盖；旧任务和旧 Edge 不报协议或页面错误。
