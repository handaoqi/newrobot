# 路径规划页定位尝试过程可视化与最优位姿选择计划

## 目标

在路径规划页“下发地图”“初始化定位”“主动重定位”三个操作中，按候选尝试顺序在地图上展示定位点，并在验证完成后选择一个最优匹配位置作为当前机器狗的地图位姿。

## 最优位姿选择规则

1. 候选必须先通过质量门：NDT/GICP 收敛、score/误差、内点率、连续稳定帧和位姿跳变限制。
2. 只在质量门通过后参与排序，未通过的候选不得修改正式定位。
3. 排序优先级固定为：
   - 连续稳定帧数更多；
   - GICP/ICP 内点率更高；
   - NDT score 更低；
   - 几何残差/RMSE 更低；
   - 与候选种子距离和 yaw 跳变更小。
4. 取排序第一的候选作为 `best_match_pose`，但必须再次连续验证 2～3 帧。
5. 连续验证通过后，原子更新 `map→base_link` 当前位姿、可信位置和定位状态；不得逐个候选直接覆盖正式位姿。
6. 所有候选均失败时，保持原定位状态，回退现有 Tier 2/人工初始点，并返回完整候选结果。

## 数据与界面

- Edge 为每个候选发送 `started/verifying/accepted/rejected/failed` 状态，包含稳定的 `candidate_number`、可读 `candidate_label`（原点航向或周边方向/距离）、候选 x/y/yaw、当前实时 x/y/yaw、NDT/GICP 指标和拒绝原因。
- 云端复用命令生命周期保存本次会话，当前操作开始时清空旧结果，结束后保留最后一次结果。
- 路径规划页增加可展开“定位尝试过程”卡片；候选按序号展示，地图用编号和颜色区分等待、尝试中、失败、成功，实时机器人位置使用独立图标。
- 当前验证会明确提示“正在验证候选 #N / 点名”；最优结果和提交事务都明确显示候选 #N、种子、匹配位姿、NDT score、内点率和收敛结论。提交后 FAST-LIO 接管失败时，仍保留该候选和指标，避免被下一阶段进度覆盖。
- “下发地图”仅在进入地图定位阶段后显示候选；文件传输阶段显示命令进度。

## 验收

- 三个按钮均能看到逐个候选的序号、点名、状态和实时 x/y/yaw。
- 错误候选不会进入正常定位状态。
- 最终只提交一个 `best_match_pose`，页面显示所提交的候选编号、来源、NDT score、内点率和收敛指标。
- 刷新页面不会改变当前会话候选顺序；新操作会清空旧会话。
- 失败时地图和正式定位不被错误候选污染。
